## DIY Predictions Championship

For the 2025 season, every one of us wrote our predictions in the Notes app and dropped them into the group chat. It worked well enough until the end of the season, when we had to actually score them.

<Alert variant="error" title="Issues caused by this">

- There was no single source of truth. Predictions lived across a dozen screenshots buried in months of chat history.
- Nothing stopped a vague prediction. _"Someone crashes out in the wet"_ is impossible to settle when everyone remembers it differently.
- Nothing was locked. A note can be quietly edited mid-season, and a screenshot only proves what it looked like on the day it was taken.

</Alert>

The format itself was okay - writing a list of bullet points is quick and convenient. What was missing was structure, validation and a layer of visibility across everyone's predictions.

## Adding Structure to the Freedom of Notes

The standard approach here would be a form: 16 input fields, a dropdown per tier and a submit button. It would have been easy to validate, but it would have turned a fun, opinionated ritual into data entry. People need the freedom and space to marinate on their predictions, so a plain form might have been too constraining.

Instead, I kept the text-first format and built the structure underneath it. The card editor is a lightweight code editor (built using `react-simple-code-editor`) with a custom Prism grammar, so tier headers, comments and predictions each get their own highlighting:

```text
// TIER 1: Expected. [1 point]
- Max Verstappen wins in Suzuka
- ...

// TIER 4: No way fam. [6 points]
- Nico Hülkenberg earns his first career podium
- ...
```

Each tier header carries an actual example based on drivers' and teams' history, so the scale of _'expected'_ versus _'no way'_ is set by our own history instead of a rules page.

## Turning Free Text into a Card

A custom parser reads the editor line by line. `// TIER` headers switch the active tier, a hyphen bullet (`-`) starts a new prediction, and any other line is treated as a continuation of the previous one, so a long prediction can wrap naturally without breaking the format.

Validation then runs as a set of game rules rather than form errors:

1. **Exactly four per tier.** _"Tier 3 has 5 predictions. It must have exactly 4."_
2. **No vague predictions.** Every prediction has to mention a driver, team principal, team or track, checked against a dictionary of 148 F1 keywords. Otherwise it's rejected as _"too vague."_

The second rule solved last season's biggest argument at the point of entry. It also did a second job for free: the keyword it finds is mapped to a driver or team image, so every prediction on the finished card has a face next to it. One pass over the text gives me both the validation and the visuals.

## Invite-Only, Without Passwords

This was built for a group of friends, so access was based on an invite-only mechanism. The usual options would have been an auth provider like Clerk or NextAuth with Google sign-in. However, it felt a bit unnecessary for my users to create a password for a product they'd use maybe two or three times a year.

Instead, I built a passwordless flow based on an allowlist.

- When a user attempts to sign up to the platform, their email is checked against a predefined `allowed_users` table in Neon. Whether or not it's on the list, the response is identical, so the list can't be probed to find out who's in it.
- If it is on the list, a six-digit code is emailed through Nodemailer. Codes expire after 15 minutes and are marked as used on verification to prevent replays.
- A successful code signs a JWT (`jose`) into an `httpOnly` cookie with a one-year expiry. The championship runs for a full season, so nobody should have to log in again mid-way through.

## Locking It In

Once a card is submitted, the editor route redirects away for that user, so predictions can't be revisited after the fact. That one rule replaced the honour system of the Notes app.

The Pitwall page then shows the card of every player who has locked theirs in. It reads from the `predictions` table, so anyone who hasn't submitted yet simply doesn't appear, and the allowlist is only used to look up display names. It's also locked until you've submitted your own card, so nobody can borrow inspiration from someone else's predictions or deliberately copy them. Last season, comparing predictions meant scrolling back through the group chat. Now it's one page.

## Making It Feel Like F1

Since the point was to make the championship more fun, I spent time on the moments around the core flow:

- **Lights out.** The first visit in a session plays the F1 start sequence: five red lights come on one by one, hold, then go out to reveal the logo. It's tracked in `sessionStorage` so it never gets in the way twice.
- **Draggable photos.** The login page has photos from races I've been to, as tilted cards with spring physics (`motion`) that you can pick up and throw around.
- **Tone of voice.** _"Enter paddock"_ on the login button, _"Yep, we're that selective"_ under the email field, _"Rolling you out to the grid"_ on success, and _"Lock them in"_ to submit.

## Takeaways

The key decision on this project was to not replace a behaviour people already had. A form would have been simpler to build, but the editor kept the part of the Notes app everyone liked and quietly added the rules we were missing.

There are a few things I'd change next season:

1. **Automatic tracking for quantitative predictions.** Something like _"Carlos Sainz beats Lewis Hamilton in the standings"_ can be settled by data instead of memory. Parsing these into a structured rule (two drivers, a comparison, a source) and checking it against a public F1 results API after each race would keep a live score without anyone having to tally it at the end.
